# PM-Prototype-Skill 使用说明（可分发版）

> 给产品经理/团队同事：这个 skill 是「Hermes 交互原型设计工作流」的规范，配合 Hermes Agent 使用。
> 本文档可分享；skill 本体在接收方 Hermes 环境中配置后生效（见「占位符表」）。

## 一、这是什么

一个**面向产品经理的交互原型设计 skill**。你（产品经理）提出需求，Hermes 按强制协议执行：

```
你提供（三选一或组合）
  ① 设计软件 MCP 链接（如 MasterGo）
  ② 设计稿截图 + 优化诉求
  ③ 纯文字优化诉求
        ↓
Hermes 多轮澄清（一次一问，理解交互细节）
        ↓
复述确认（你点头后）
        ↓
基于设计规范出稿（线框图 / 高保真 / 评审报告）
```

**核心承诺**：Hermes 不会在没搞清楚你的设计意图前就出稿。它会像一位资深产品同事一样，先问透，再动手。

## 二、你会体验到的流程

1. **第一步：复述理解**——Hermes 收到设计稿/截图后，先输出"我读到了什么"：
   - 页面结构（自上而下）
   - 交互要点（入口/跳转/状态/反馈）
   - 它不确定的地方（存疑清单）
2. **第二步：逐项追问**——一次一个问题（可点选的选项），围绕：
   - 入口与跳转（这个元素点了去哪？）
   - 模式与状态（并列还是层级？切换后什么变什么不变？）
   - 数据归属（设备状态还是模式属性？）
   - 反馈与边界（误操作/空态/离线怎么办？）
3. **第三步：确认后出稿**——你确认理解无误，Hermes 才加载设计规范开始设计。

## 三、设计规范对接

- **Maygrove 项目**：自动加载 `maygrove-design-system`（森林绿 #1A5A3F + 骨白 + 琥珀，大留白，深浅双主题）
- **其他品牌**：Hermes 会先问你品牌的配色/字体/圆角，**不会**擅自套用历史项目风格

## 四、交付物三档（按需选择）

| 档位 | 产出 | 用途 |
|---|---|---|
| L1 线框图 | .excalidraw（可拖入 excalidraw.com 编辑） | 快速对结构，迭代快 |
| L2 高保真原型 | 可交互 HTML（点按/跳转/Toast/状态切换，深浅模式） | 给用户/开发演示真实交互 |
| L3 评审报告 | 问题清单 + 建议（不改稿） | 现有设计走查 |

默认交付中文文件名，存放 `hermes_delivery/`，可部署到 Forgejo Pages 生成线上预览链接。

## 五、占位符表（接收方配置）

> 分享给同事后，对方需要按自己环境替换以下占位符：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{品牌规范skill名}` | 品牌设计 token skill（无则先收集 token） | maygrove-design-system |
| `{设计软件MCP}` | 设计稿读取通道（无则用截图） | mastergo-mcp-handoff |
| `{部署仓库}` | Forgejo 部署仓库本地路径 | ~/krisays2 |
| `{部署域名}` | Pages 域名 | kris.pages.sino-beta.com |
| `{交付目录}` | 交付物目录 | ~/hermes_delivery/ |
| `{界面语言}` | 目标用户语言 | en / zh |

## 六、本地安装（接收方）

```bash
# 1. 将 skill 目录复制到 Hermes skills 目录
cp -r pm-prototype-skill ~/.hermes/skills/product-management/

# 2. 确认 skill 可见
hermes skills list | grep prototype

# 3. 关联 skill（按需）：
#    - 设计稿读取：mastergo-mcp-handoff（需 MasterGo token，团队版）
#    - 品牌规范：maygrove-design-system 或自定义
```

## 七、使用示例

> 「这个 MasterGo 链接的设计稿，我想优化它的模式切换交互，帮我出个高保真原型」

Hermes 将：
1. 通过 MCP 读取设计稿 DSL → 复述页面结构
2. 一次一问追问：模式是并列还是嵌套？切换后设备参数变不变？入口发现性要求多高？……
3. 你确认理解 → 加载设计规范 → 输出可交互 HTML → 部署 Pages 给你预览链接
