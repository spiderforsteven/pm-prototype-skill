# PM-Prototype-Skill 使用说明（可分发版）

> 给产品经理/团队同事：这是「AI 交互原型设计工作流」的规范，配合主流 AI Agent（Hermes / Cursor / Claude Code / Codex / Cline）使用。
> 本文档可分享；skill 本体在接收方环境中配置后生效（见「占位符表」）。

## 一、这是什么

一个**面向产品经理的交互原型设计 skill**。你提出需求，AI 按强制协议执行：

```
你提供（三选一或组合）
  ① 设计软件 MCP 链接（如 MasterGo）
  ② 设计稿截图 + 优化诉求
  ③ 纯文字优化诉求
        ↓
AI 多轮澄清（一次一问，理解交互细节）
        ↓
复述确认（你点头后）
        ↓
问设计 token（你自备优先，无则用预置）
        ↓
出稿（线框图 / 高保真 / 评审报告）
```

**核心承诺**：AI 不会在没搞清楚你的设计意图前就出稿。像一位资深产品同事，先问透，再动手。

## 二、你会体验到的流程

1. **第一步：复述理解**——AI 收到设计稿/截图后，先输出「我读到了什么」：页面结构、交互要点、不确定项清单
2. **第二步：逐项追问**——一次一个问题，围绕：入口与跳转、模式与状态、数据归属、反馈与边界
3. **第三步：确认后出稿**——你确认理解无误，AI 才进入设计

## 三、设计 Token（每次会问你）

进入设计前，AI 会先问：**「你有自己的设计 token 吗？」**

| 你的情况 | 做法 |
|---|---|
| 有品牌设计规范 | 直接粘贴色值 / 上传 token 文件（JSON/YAML/DESIGN.md/截图） / 提供品牌官网让 AI 提取 |
| 没有 | AI 使用预置默认 token（欧美 App 通用风格：Apple HIG/Uber/BirdBuddy 基线——中性灰阶、占位系统蓝、系统语义色、深浅双主题），交付时注明「默认欧美 token」 |

> 每次使用都会问，方便你随时切换品牌。

## 四、交付物三档（按需选择）

| 档位 | 产出 | 用途 |
|---|---|---|
| L1 线框图 | .excalidraw（可拖入 excalidraw.com 编辑） | 快速对结构 |
| L2 高保真原型 | 可交互 HTML（点按/跳转/Toast/状态切换，深浅模式） | 给用户/开发演示 |
| L3 评审报告 | 问题清单 + 建议（不改稿） | 现有设计走查 |

## 五、适配主流 AI Agent

| Agent | 接入方式 |
|---|---|
| Hermes Agent | 复制 `pm-prototype-skill/` 到 `~/.hermes/skills/product-management/` |
| Cursor | 项目根目录建 `.cursor/rules/pm-prototype.mdc`，内容：`读取 AGENTS.md，按启动协议执行。` |
| Claude Code | `CLAUDE.md` 追加：`读取 pm-prototype-skill/AGENTS.md，按启动协议执行交互原型设计任务。` |
| Codex / Cline | 把 `AGENTS.md` 复制到项目根目录（通用约定），或对话开头引用协议 |

## 六、占位符表（接收方配置）

> 分享给同事后，对方按自己环境替换：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{设计软件MCP}` | 设计稿读取通道（无则用截图） | MasterGo MCP / Figma MCP |
| `{默认设计token}` | 预置 token（见 references/design-tokens.md） | 欧美通用默认（Apple/Uber/BirdBuddy 中性风） |
| `{部署仓库}` | 交付物部署位置（可选） | 本地 / Pages / 云盘 |
| `{界面语言}` | 目标用户语言 | zh / en |
| `{Agent类型}` | 你用的 AI 工具 | Hermes / Cursor / Claude Code / Codex |

## 七、使用示例

> 「这个 MasterGo 链接的设计稿，我想优化它的模式切换交互，帮我出个高保真原型」

AI 将：
1. 通过 MCP 读取设计稿 DSL → 复述页面结构
2. 一次一问：模式是并列还是嵌套？切换后设备参数变不变？入口发现性要求多高？……
3. 你确认理解 → 问设计 token → 输出可交互 HTML 原型
